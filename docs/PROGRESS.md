## 1. 목표

구조 축(AlphaFold3)과 결합 축(Boltz-2)의 판정 결과를 하나의 종합 판정 화면에서 교차검증함.

작업 전에는 두 축이 서로 다른 화면에서 따로 판정되었고, 리포트 화면(s5)에서도 축별 행으로 나열될 뿐이었음. 사례 단위로 구조 판정과 결합 판정을 묶어 읽을 자리가 없었음.

- 구조 축: 변이 잔기 8 Å 이내 Cα 국소 RMSD가 음성 대조군(같은 서열 모델 쌍)의 변동을 넘는지 판정
- 결합 축: 복합체 ipTM의 대립형질 간 차이가 같은 대립형질 안의 변동을 넘는지 판정

구조가 변하지 않아도 결합이 변할 수 있고 그 반대도 가능하므로 두 축을 함께 봄. 어느 축에서도 감별되지 않는 경우는 "효과 없음"이 아니라 "계산 모델의 감별 한계"로 보고함.

## 2. 방향: s5 리포트 화면에 종합 판정 (2×2 규칙)

### 붙이는 위치

새 화면을 만들지 않고 기존 s5(리포트)를 확장함.

- `app/index.html`의 `판정 요약` 패널(현재 412행) 위에 종합 판정 패널 `#rMatrix`(현재 409~410행)를 추가
- 기존 `#rTable`(축별 상세 행)은 근거 표로 그대로 둠
- 위계: 위쪽은 사례별 종합 결론, 아래쪽은 축별 근거 상세

선택 근거

- 작업 당시 s5는 `RMSD`와 `IPTM` 두 원자료를 모두 불러오는 유일한 화면이었음. 현재는 두 원자료를 `computeStructureVerdict`, `computeBindingVerdict`가 불러옴(`app/app.js` 322행의 `RMSD`, `IPTM`)
- 화면 설명이 이미 "전 사례 판정 요약"임
- 내비게이션 순서 `홈, 분석, 구조 검증, 결합 인터페이스 검증, 리포트, 방법론`이 "입력, 축별 검증, 종합, 방법" 순서임. s4와 s5 사이에 넣거나 s6 뒤에 붙이면 이 순서가 깨짐
- 라우팅 훅 `if(id==='s5') renderReport();`(`app/app.js` 591행, 689행)를 그대로 재사용하므로 라우팅을 바꾸지 않음
- 새 화면 s7은 채택하지 않음. 내비게이션이 7개로 늘고, `app/slides/`의 스크린샷 10장과 `DOC_CALLOUTS` 구성과 어긋나며, s5와 역할이 대부분 겹침

### 2×2 판정 규칙

구조 축 판정과 결합 축 판정의 네 조합임.

| | 결합 축: 변동성 초과 | 결합 축: 변동성 내 |
|---|---|---|
| 구조 축: 변동성 초과 | 양축 감별 | 구조만 감별 |
| 구조 축: 변동성 내 | 결합만 감별 | 양축 미감별 |

다섯 번째 상태로 "결합 축 미측정"을 둠. 작업 당시에는 CD33과 PILRA가 해당했고, 현재는 CD33만 해당함. 빈 값을 "차이 없음"으로 표시하지 않음. 미측정과 미감별은 다른 결론임.

### 두 축의 차이 (작업 당시)

아래 표는 작업 시작 시점(2026-09-02)의 구현을 적은 것임.

| | 구조 축 | 결합 축 |
|---|---|---|
| 대상 | 3개 사례 (인자로 전환) | TREM2 하드코딩, 인자 없음 |
| 검정 | `mannWhitneyU(sig, noise, 'greater')` 단측 | `mannWhitneyU(mut, wt, 'two-sided')` 양측 |
| 귀무가설 | 변이 편차가 재현 변동을 초과하지 않음 | 두 군의 ipTM 분포가 같음 |
| 단위 | Å (클수록 신호) | ipTM (무차원, 방향 없음) |
| 효과크기 | `ms/mn` 비 | `spread` 대비 `d` |

당시에는 두 축의 귀무가설이 달라, `det` 불리언을 AND나 OR로 합치면 서로 다른 가설을 섞게 되는 문제가 있었음. 그래서 2×2는 두 판정을 합성하지 않고 나란히 배치해 읽는 매트릭스로 설계함.

이후 변경 (2026-09-03)

- 두 축 모두 `permutationP`(`app/app.js` 120행) 라벨 순열검정, 단측, α = 0.05로 통일함. 결합 축도 ipTM 쌍 차이 `|ipTM_i − ipTM_j|`로 바꿔 구조 축과 같은 음성 대조군 쌍 설계를 씀.
- 결합 축은 `computeBindingVerdict(gene)`으로 사례를 인자로 받음. 대상은 `BIND_ALLELES`의 TREM2와 PILRA임.
- `mannWhitneyU`는 판정에 쓰지 않음. 쌍 행렬이 불완전해 순열을 돌릴 수 없을 때의 대체값 `pMW`로만 남아 있음.
- 귀무가설과 검정이 같아진 뒤에도 측정 대상이 구조 편차와 결합 신뢰도로 다르므로 두 판정을 합성하지 않는 설계는 그대로 둠.

현재 판정 (`results/`의 CSV를 `src/detectability.py`로 다시 계산한 값. 앱의 `permutationP`와 같은 알고리즘)

| 사례 | 구조 축 p | 판정 | 결합 축 p | 판정 | 결합 파트너 |
|---|---|---|---|---|---|
| CD33 R69G | 0.65 | 변동성 내 | 없음 | 미측정 | 시알산(당). 단백질-단백질 예측 설계 범위 밖 |

- 위 p는 모두 라벨 순열검정 값임(2026-09-03 전환). 쌍의 비독립성을 교정한 값이며 판정은 전환 전후로 바뀌지 않음.

- 결합 축 쌍 차이 중앙값: TREM2는 음성 대조군 0.0457(210쌍), 처리군 0.0434(225쌍), 비 0.95×. PILRA는 음성 대조군 0.0577(90쌍), 처리군 0.0460(100쌍), 비 0.80×.

이전 검정 값 (이력)

순열검정 전환 전에는 Mann-Whitney U를 썼음. 같은 CSV에 SciPy를 적용해 다시 확인한 값임.

| 사례 | 축 | 이전 검정 | 이전 p | 현재 p (순열검정) |
|---|---|---|---|---|
| CD33 R69G | 구조 | 쌍 값에 Mann-Whitney 단측 | 0.54 | 0.65 |
| PILRA R78G | 구조 | 쌍 값에 Mann-Whitney 단측 | 6×10⁻⁹ | 0.0079 |
| TREM2 R62H | 구조 | 쌍 값에 Mann-Whitney 단측 | 5.4×10⁻³ | 0.0079 |
| TREM2 R62H + Aβ42 | 결합 | 두 군 ipTM 직접 비교, Mann-Whitney 양측 | 0.30 (정규근사 0.2998, 정확검정 0.3046, U = 87) | 0.80 |
| PILRA + NPDC1 | 결합 | 두 군 ipTM 직접 비교, Mann-Whitney 양측 | 0.85 (정규근사 0.8501, 정확검정 0.8534, U = 47.0, G78 기준) | 0.97 |

- PILRA 결합 축은 시드 1만 있던 단계(n = 5 + 5)에서 정규근사 0.8345, 정확검정 0.8413(U = 11.0)이었음. 같은 단계의 자료에 현재 순열검정을 적용하면 전수 126분할로 p = 0.79임.
- 어느 방식에서도 판정은 변동성 내로 같음.

TREM2는 "구조 축 초과, 결합 축 변동성 내" 칸에 놓임. 다만 구조 축의 효과크기는 작음.

- 국소 RMSD 중앙값 차 +0.089 Å(1.53배)임. 음성 대조군 범위 0.069~1.250 Å와 처리군 범위 0.163~1.187 Å가 크게 겹침.

TREM2 결합 축의 원시 ipTM 중앙값은 WT 0.851, R62H 0.824임(`results/boltz_summary.md`). 순열검정 p = 0.80으로 변동성 내이며, 이전 검정에서는 p = 0.30이었음. Bret et al. 2026의 결합부위 변이 둔감성 보고와 같은 방향임.

### 2단계: CD33, PILRA (나중)

작업 당시 두 사례는 결합 축 데이터가 없었고, 만들려면 예측 실행이 먼저 필요했음. PILRA는 2026-09-03에 실행함(6절). CD33은 실행하지 않음.

당시 정리한 선결 과제

1. 결합 파트너 조사. TREM2는 Aβ42라는 문헌 근거가 있음(Zhao 2018 Neuron, Zhong 2018 Mol Neurodegener). CD33과 PILRA도 상응하는 파트너를 문헌에서 확정해야 함. 임의로 고르지 않음
2. Boltz-2 예측 실행. 사례당 대립형질 2 × 시드 3 × 모델 5 = 30구조. GPU 필요
3. 입력 구간 결정. TREM2는 Ig 도메인 19~130을 썼음(`src/make_boltz_inputs.py`). 사례마다 인터페이스 지표를 흐리지 않는 구간을 따로 정해야 함

당시 필요했던 스키마 변경

- `results/boltz_iptm.csv`와 `app/data/boltz_iptm.csv`는 `allele` 값이 `WT`, `R62H`뿐이었고 `gene` 칼럼이 없었음. 단일 사례를 전제한 스키마라 여러 사례로 넓히려면 칼럼을 추가해야 했음
- `CASES` 상수(`app/app.js` 15~25행)에도 결합 축 관련 필드가 없었음(`wtCif`, `mutCif`, `img`는 모두 구조 축용)

이후 변경: `gene` 칼럼을 추가했고(6절), 결합 축의 대립형질 라벨과 파트너는 `CASES`가 아니라 별도 상수 `BIND_ALLELES`(`app/app.js` 359행)에 둠.

### 작업 당시 확인한 사항

- 판정 결과가 어디에도 저장되지 않았음. `det`, `p`, `mn`, `ms`가 모두 렌더 함수의 지역 변수였고 HTML 문자열로 쓰인 뒤 버려졌음. 함수 밖으로 나가는 것은 `window._curGene` 하나뿐이었음. 종합 판정을 붙이려면 이 부분을 먼저 정리해야 했음. 현재는 두 compute 함수가 판정 객체를 반환하고 `VERDICT_CACHE`(`app/app.js` 323행)에 보관함
- 업로드 경로(`window._userResult`, `app/app.js` 811행)는 당시 유일하게 결과를 객체로 보존했음. `{baseline, signal, p, detected, nFit, usedCore, pos, label, acc, ...}` 형태이며 상태 설계의 선례로 참고함
- 업로드 경로에는 구조 축만 있고 결합 축이 없음. 종합 판정 적용 범위에서 제외함
- `app/data/*.csv` 3개는 `results/`의 수동 사본임. 파이프라인을 다시 돌리면 직접 맞춰야 함
- 당시에는 파이썬(SciPy)과 웹 앱(JS 자체 구현)이 Mann-Whitney 검정을 각각 구현하고 있었음. 현재는 `src/detectability.py`(표준 라이브러리)와 `app/app.js`가 같은 순열검정 알고리즘과 같은 PRNG(mulberry32)를 씀
- `mannWhitneyU` 안의 `const U = alternative==='greater' ? U1 : U1;`(`app/app.js` 57행)은 양쪽 분기가 같아 의미가 없는 줄임. 기능에는 영향이 없어 고치지 않음

## 6. 2단계 진행 (2026-09-03): PILRA + NPDC1

입력

- `src/make_boltz_npdc1_inputs.py`로 YAML 4개를 생성함(`PILRA_{G78,R78}_{NPDC1,alone}.yaml`). PILRA 32~150 + NPDC1 35~181 = 266 aa
- UniProt 정본이 R78이므로 정상형이 G78임. 기존 `PILRA_dom_WT.fasta`(R78)와 라벨이 반대임

결과

- ipTM은 조건당 10개임(시드 1~2 × 모델 0~4). 중앙값은 G78 0.9088, R78 0.8935(차 −0.015)
- 판정은 변동성 내, 미감별임
- 시드 1만 있던 n = 5 단계에서는 차가 +0.017로 부호가 반대였음(G78 0.8794, R78 0.8960). 표본을 늘리자 방향이 뒤집혔으므로 이 차이는 노이즈로 봄

스키마 확장

- `boltz_iptm.csv`에 `gene` 칼럼을 추가함. 현재 50행(TREM2 30 + PILRA 20)임. 시드 1만 있던 단계에서는 40행(TREM2 30 + PILRA 10)이었음
- `app/data/`와 `results/` 두 사본을 모두 갱신함
- PILRA 행은 `iptm`만 있고 나머지 4개 지표는 빈칸임

`src/analyze_boltz.py` 병합 처리

- `write_csv()` 헬퍼를 새로 만듦. 이 스크립트는 TREM2만 수집하므로 단순 덮어쓰기를 하면 PILRA 행이 사라짐. 수집하지 않은 사례의 기존 행을 읽어 보존하도록 고침
- 검증(기록): 가짜 TREM2 30행으로 다시 실행했을 때 당시의 PILRA 10행이 값 그대로 유지됨

미감별 원인 추정

- 매트릭스 칸에 "추정"으로 명시함
- PILRA 결합은 시알산 매개인데 Boltz-2 단백질-단백질 예측에는 글리칸이 없음. 모델의 감별 한계와 글리칸 부재를 이 결과만으로는 구분할 수 없음
- 근거: Rathore N, et al. (2018) PLoS Genet 14(11):e1007427

범위 밖으로 둔 것

- s4(결합 인터페이스 검증) 화면은 TREM2 전용으로 둠
- PILRA는 ipTM 수치만 있고 복합체 구조(.cif)가 없어 Mol* 뷰어에 띄울 대상이 없음

## 7. 미결 사항

- CD33의 결합 축은 측정하지 않음. CD33의 결합 파트너는 시알산(당)이고 현재 결합 축은 단백질-단백질 예측 설계라 이 조합을 다루지 않음. 처리 방안은 정하지 않음. 앱 매트릭스 하단 문구는 "결합 파트너를 문헌으로 확정한 뒤 Boltz-2 예측이 필요"라는 작업 당시 표현 그대로임
- PILRA 결합 축 표본은 대립형질당 n = 10(시드 1~2)임. TREM2(n = 15)보다 적음. 입력은 시드 3까지 설계했으나 시드 3은 실행하지 않음
- `#rTable`에서 구조 행과 인터페이스 행의 PILRA 표기가 갈리던 문제는 해결함. 두 행 모두 `caseLabel`의 `R78G`를 쓰고, 결합 축 데이터의 방향(G78 정상형, R78 변이형)은 표 아래 각주로 안내함
- 업로드 경로(`window._userResult`)는 구조 축만 있어 매트릭스 적용 범위 밖임
